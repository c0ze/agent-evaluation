# Containment and corrective actions

Disabling `tenant_retry_policy` preceded the sustained recovery. Keep that containment in place while verifying worker behavior. The remaining entries are proposed actions.

| Priority | Owner | Action | Verification signal | Rollback or stop condition |
| --- | --- | --- | --- | --- |
| P0 · immediate | Incident commander and worker on-call | Confirm the flag is off across the affected pools. Sample jobs eligible for retry and watch the queue through drain. | Workers acknowledge the flag version, sampled retries use the intended delay, completions outpace new arrivals during drain, and oldest-job age and checkout latency return to baseline. | Keep the flag off until the fix passes retry tests. Re-enable first for a small group of tenants. |
| P0 · during drain or recurrence | Worker on-call and database on-call | Hold further scale-out while connections are saturated. If pool waits persist, reduce worker concurrency in small steps and let in-flight work finish. | Check database connection headroom, pool waits, completed jobs per minute and oldest-job age after each step. | Stop reducing once headroom and throughput recover. If throughput falls without relieving waits, restore the last stable setting within the database connection budget. |
| P1 · before re-enabling | Worker engineering | Reproduce the observed empty-policy case. Trace policy resolution and ensure missing or invalid tenant values use the configured exponential default with a bounded retry budget. Test valid overrides and jobs already queued at rollback. | Tests capture actual scheduled delays and attempt counts. Invalid settings produce a delayed retry and repeated failures stop at the budget. Valid settings retain their specified behavior. | Ship behind the disabled flag. Revert the worker change if existing jobs or valid overrides regress. |
| P1 · before expanding rollout | Release engineering and SRE | Instrument effective retry delay, attempts per job and exhausted budgets by flag cohort. Enable the fix for a small eu-west cohort alongside a comparable flag-off cohort. Expand in steps. | Compare cohorts under representative load. Require expected delays, stable completions and checkout latency, and database headroom before each expansion. | Disable the flag and pause expansion if rapid retries recur, queue age rises or database headroom erodes. Confirm workers received the change. |
| P2 · capacity controls | Database engineering and worker platform | Size worker connection limits against the 300-connection database ceiling, reserving capacity for the API and other clients. Load-test a worker scale-out with retries active. | The test leaves the agreed reserve available, preserves API access and increases job completions without sustained pool waits. | Stage limit changes one pool at a time. Restore the previous setting if throughput regresses and keep aggregate connections within the tested budget. |
