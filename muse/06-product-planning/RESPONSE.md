# RESPONSE.md — Three riskiest assumptions

1. **One inspector edits at a time; supervisors rarely collide (PLAN.md §0.1, §5).** If supervisors routinely rewrite observation fields while inspectors are offline, the per-field "confirm each conflict" screen becomes a bottleneck and blocks submit. Mitigation: pilot dashboard tracks 409/conflict rate; if high, narrow supervisor edit permissions during active fieldwork before building anything heavier.
2. **Server `acceptedAt` clock + wipe-confirmation loop is sufficient for the 24 h rule (PLAN.md §0.7, §7).** A device that stays offline past the deadline must self-wipe on schedule and confirm later; any gap (background-task limits, tampered clock, lost device) is a compliance breach. Mitigation: MDM remote wipe as backstop, overdue-wipe alerting, and pilot acceptance test for the offline-past-deadline case.
3. **Intermittent links can carry 40 compressed photos via resumable upload (PLAN.md §0.5, §4, §6).** Basements plus flaky signal may still strand multi-hundred-MB queues, delaying submit and acceptance. Mitigation: compress-to-≤1 MB default, hash-deduped resume, Wi-Fi-preferred bulk policy, and pilot photo-completion metric as a rollout gate.
