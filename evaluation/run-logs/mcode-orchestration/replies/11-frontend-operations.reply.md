I built **Relay**, a single-page operations control room in `11-frontend-operations/` as four dependency-free files — `index.html`, `styles.css`, `app.js`, and `RESPONSE.md` — seeded from `DATA.json` (inlined in `app.js` because `fetch()` of a local file is CORS-blocked under `file://`, with `DATA.json` left as the source of truth). The page uses a flat dark neutral palette with a single blue accent carried by state rather than decoration: severity is a 3px colour rail + label so a column reads at a glance, while status is an outlined pill, so the same hue in two systems never collides. Everything numeric is mono with `tabular-nums` for column alignment, and no heading exceeds 22px. The 24-hour chart is inline SVG with a `0–100k` pinned axis, 6/12/24h re-slicing, pointer scrubbing plus arrow-key scrubbing, a "peak budget" reference line, `role="img"` with `<title>`/`<desc>`, and a visually-hidden table of every value. Filtering combines debounced search, severity checkboxes, status/service selects and sorting; the empty state names the filters that caused it rather than saying "no results". Acknowledge is a real state change — status updates in both the panel and the table row, the button becomes a disabled "✓ Acknowledged 19:04" confirmation, ownership transfers, the activity log and rail badge update, and a 7s Undo restores the exact prior status and owner. I drove the page in headless Chromium over the DevTools Protocol with real clicks and key events rather than assuming it worked, and that caught four things I'd otherwise have shipped broken: a `[hidden]` override where `display:flex` was defeating the filter-summary, empty-state and runbook toggles; `<th>` elements overflowing the 390px viewport (masked by `overflow-x: hidden`, so I audited every element's bounding box, not just page scrollWidth); the activity log prepending out of time order; and — after measuring rather than eyeballing — `--text-faint` at 3.98:1, a genuine WCAG AA failure I corrected to `#8791a0` (5.6:1). All 45 assertions pass with no console errors, including a contrast audit of 121 rendered text nodes at 0 below AA. I removed my verification scaffolding afterwards, so the directory holds only the four deliverables plus the original `DATA.json`/`TASK.md`; at 390px the rail becomes a bottom tab bar and the table becomes self-labelling cards with `scrollWidth` = `clientWidth` = 390.

**Every deliverable is complete:** `index.html`, `styles.css`, `app.js`, `RESPONSE.md`. One caveat worth flagging: the nav items other than Incidents are placeholders, acknowledgement isn't persisted across reload, and the throughput series is static seed data rather than a live feed — all noted under "Known scope limits" in `RESPONSE.md`.
