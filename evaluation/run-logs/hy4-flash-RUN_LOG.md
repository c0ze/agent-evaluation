## How it was run

Each of the 13 tasks ran as its own `codebuddy -p` session, so every task started with a fresh context. Each call carried the same instruction the other runs gave, with only the task directory filled in. One ran at a time, and the three CodeBuddy models in this batch ran one after another (HY4, then HY4 Flash, then DeepSeek V4.1 Flash). The command was `codebuddy -p <instruction> --model custom-local:hy4-flash --effort high --setting-sources project --strict-mcp-config --no-session-persistence --permission-mode acceptEdits --disallowedTools WebFetch WebSearch --settings <rules> --output-format stream-json`, run from the repository root.

Isolation: this repository was created fresh from the task templates, with no history, outside the user's home directory, so no `CLAUDE.md`, `CODEBUDDY.md` or `AGENTS.md` was discovered. CodeBuddy's sign-in is tied to the user's real HOME (a clean HOME failed to authenticate), so HOME stayed real. User settings (plugins, hooks), MCP servers, session persistence and auto-memory were off. A smoke test reported no instruction files, memories, plugins or MCP tools, only one built-in skill, and no memory files appeared during the run. CodeBuddy ignores Claude Code's sandbox settings and its own sandbox needs Docker, so permission rules stood in for one: Bash allowed, but `curl`, `wget`, `pip`/`npm install`, `npx`, `uv pip`/`uv add`, `git clone`, `ssh` and the web tools denied (tested, including inside compound commands). The transcripts were audited afterwards.

The orchestrator gave no hints and did not review, fix, finish or re-run any work beyond the re-runs noted below. CodeBuddy reports no cost for plan usage ($0 in every result event); tokens come from each session's final `result` event.
