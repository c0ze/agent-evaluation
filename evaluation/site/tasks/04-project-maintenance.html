Why normalize_version is a pass-through

The task requires no change in observable behaviour for ordinary versions, so the first step was to measure what the old code did. LooseVersion.__str__ is literally return self.vstring, and on Python 3.10 every one of 20 sample strings came back unchanged ('1.0-rc1' -> '1.0-rc1', '01.02' -> '01.02', 'v1.0' -> 'v1.0', ' 1.0 ' -> ' 1.0 ', '1.2.3.foo' -> '1.2.3.foo'). The obvious replacement, packaging.version.Version, was measured too (packaging 24.0): '1.0-rc1' -> '1.0rc1', '01.02' -> '1.2', 'v1.0' -> '1.0', '1.0.RC1' -> '1.0rc1', ' 1.0 ' -> '1.0', and '1_0' / '1.2.3.foo' raise InvalidVersion. That is a behaviour change plus a new runtime dependency, so it was rejected. Whether the function should do more is item 2 in MAINTENANCE.md.

Changelog

All notable changes to slugkit are documented here. The format follows Keep a Changelog. Releases before 0.4.0 predate this file and are not reconstructed.

[0.4.0] - Unreleased

Changed

  • Python support. Python 3.9 is no longer supported; requires-python is now >=3.10. Python 3.13 is now validated in CI, so the supported range is 3.10 through 3.13.
  • normalize_version no longer uses distutils. distutils is deprecated since Python 3.10 and was removed from the standard library in 3.12; the old implementation only kept importing where setuptools happened to install its compatibility shim. Output for ordinary version strings is unchanged: the input is returned exactly as given, including pre-release suffixes ("1.2.0" -> "1.2.0", "2.0rc1" -> "2.0rc1"), and strings that PEP 440 would canonicalise (such as "1.0-rc1") are still returned untouched.
  • normalize_version("") now raises ValueError instead of an AttributeError escaping from distutils. Non-string input still raises TypeError.

Fixed

  • slugify collapses repeated punctuation and whitespace into a single hyphen consistently ("Hello,,, World!!!" -> "hello-world", "a--b__c!!d" -> "a-b-c-d"). This was already present in the code before this release was prepared and is now covered by tests.

Known limitations

  • slugify does not transliterate non-ASCII letters; they are dropped along with surrounding punctuation, so "Crème brûlée" becomes "cr-me-br-l-e". This is not fixed in 0.4.0.

Internal

  • CI: the test matrix covers Python 3.10, 3.11, 3.12 and 3.13; linting runs in its own job (ruff check plus ruff format --check); the workflow token is restricted to contents: read and checkout no longer persists credentials. Actions remain pinned to actions/checkout@v4 and actions/setup-python@v5.
  • Packaging: py-modules = ["slugkit"] is declared explicitly. Without it, setuptools' flat-layout auto-discovery aborted the build with "Multiple top-level modules discovered in a flat-layout: ['slugkit', 'test_slugkit']", so pip install -e . did not work. The ruff target-version is now py310, and ruff is pinned through a dev extra.
  • Tests: added coverage for normalize_version (identity on ordinary and non-canonical inputs, whitespace preservation, error cases, a differential check against distutils where it is still importable, and a fresh-interpreter check that importing and calling the module neither imports distutils nor emits warnings) and for slugify (repeated punctuation, separator-only input, and the non-ASCII limitation above).

Maintenance guide

Release checklist

  1. Bump version in pyproject.toml and make sure CHANGELOG.md has a section for it: user-visible changes first, internal work under "Internal", and known limitations stated rather than implied fixed. Replace "Unreleased" with the release date.
  2. Run the same checks CI runs, on the oldest and newest supported interpreters at minimum: ruff check ., ruff format --check ., python -m unittest -v.
  3. Build the distribution (python -m build) and inspect the wheel: it must contain slugkit.py only, never test_slugkit.py.
  4. Install the wheel into a fresh virtual environment on Python 3.12 or newer created with python -m venv --without-pip (so no setuptools shim is present) and run python -W error -c "import slugkit; print(slugkit.normalize_version('1.2.0'))".
  5. Tag the commit v<version>, push the tag, publish, and confirm CI is green on the tag.

Compatibility policy

  • Interpreters. 0.4.x supports CPython 3.10 through 3.13, which is exactly what CI tests and the classifiers list. A new CPython minor version is added to the matrix and classifiers once it is final and the suite passes on it. A version is dropped only in a minor release, after its upstream end of life, with a CHANGELOG.md entry and a matching bump of requires-python and [tool.ruff] target-version.
  • requires-python is a lower bound only. No upper bound is declared: an upper bound would block installs on newer interpreters that work, and the tested range is communicated through the classifiers and CI instead.
  • Dependencies. The runtime has none and should stay that way; the standard library is enough for what the package does. Development tooling is pinned in the dev extra.
  • Behavioural contracts. normalize_version returns any non-empty string unchanged and raises TypeError / ValueError for non-string / empty input. slugify output for a given input is part of the public contract. Changing either is a user-visible change that needs a minor version bump and a changelog entry; do not slip it into a patch release.
  • GitHub Actions. Actions are pinned to major versions (actions/checkout@v4, actions/setup-python@v5) and the workflow runs with contents: read only. Raising a major version is a deliberate, reviewed change, not a drive-by edit.

Next three maintenance items, in priority order

  1. Python 3.14 in, Python 3.10 out. CPython 3.14 has been final since October 2025 and is not yet in the tested range; CPython 3.10 reaches end of life in October 2026. Add 3.14 to the CI matrix and classifiers now (it needs no code change in principle, but must be verified), then drop 3.10 in 0.5.0 per the policy above.
  2. Decide what normalize_version should actually do. Since 0.4.0 it is an explicit pass-through with input validation, which is what the distutils-based version always was. The name promises more. Either document the pass-through as the intended contract, or add a separate canonicalising function (PEP 440 rules, either via packaging or a small vendored regex) and deprecate the old name over a release cycle. The tests in test_slugkit.py show exactly which inputs a canonicaliser would change (1.0-rc1, 01.02, v1.0, ...).
  3. Non-ASCII handling in slugify. Non-ASCII letters are currently dropped rather than transliterated. Evaluate a dependency-free step (unicodedata.normalize("NFKD") followed by an ASCII fold) before touching the regex. This changes output for existing inputs, so it is a 0.5.0 change with tests and a changelog entry, not a patch.

Backlog beyond these: add python -m build plus a wheel-content check to CI, and enable automated dependency/actions update PRs so the pinned ruff and action majors do not go stale.

"""Small slug and version helpers."""

import re

__all__ = ["normalize_version", "slugify"]


def slugify(value: str) -> str:
    """Return a lowercase ASCII slug for ``value``.

    Surrounding whitespace is removed, the text is lower-cased, and every run of
    characters outside ``[a-z0-9]`` (whitespace, punctuation, underscores and any
    non-ASCII letters) becomes a single hyphen; leading and trailing hyphens are
    stripped.  Non-ASCII letters are dropped, not transliterated (a known
    limitation; see MAINTENANCE.md).
    """
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes.

    Releases before 0.4.0 implemented this as
    ``str(distutils.version.LooseVersion(value))``.  ``LooseVersion.__str__``
    returns the string it was given, so for every non-empty string the result is
    the input itself: ``"1.2.0"`` -> ``"1.2.0"``, ``"2.0rc1"`` -> ``"2.0rc1"``,
    ``"1.0-rc1"`` -> ``"1.0-rc1"``.  ``distutils`` is deprecated since Python 3.10
    and absent from the standard library since Python 3.12, so that contract is
    now kept without it.  No PEP 440 canonicalisation is performed.

    Raises:
        TypeError: if ``value`` is not a ``str`` (unchanged from earlier releases).
        ValueError: if ``value`` is empty (earlier releases let an
            ``AttributeError`` escape from ``distutils``).
    """
    if not isinstance(value, str):
        raise TypeError(f"version must be a str, not {type(value).__name__}")
    if not value:
        raise ValueError("version string must not be empty")
    return value

import re


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")

    """Return a version string in the form ``slugkit`` has always returned it.

    This replaces ``str(distutils.version.LooseVersion(value))``. ``distutils`` was
    removed from the standard library in Python 3.12, and ``LooseVersion`` only
    ever handed back the string it was given, so the same result is produced here
    without a parser: ordinary versions such as ``"1.2.0"`` and pre-release
    versions such as ``"2.0rc1"`` are returned unchanged. No canonicalisation is
    applied, so ``"1.0-rc1"`` stays ``"1.0-rc1"``.

    string (the old implementation raised ``AttributeError`` for the latter).

    if not isinstance(value, str):
        raise TypeError(f"version must be a str, not {type(value).__name__}")
    if not value:
        raise ValueError("version must not be empty")
    return value

import re


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes.

    Up to 0.3.x this returned ``str(distutils.version.LooseVersion(value))``.
    ``LooseVersion.__str__`` returns the string it was given, so for any
    non-empty string the result was the input unchanged (``"1.02"`` stays
    ``"1.02"``, ``"2.0rc1"`` stays ``"2.0rc1"``). That contract is kept here
    without ``distutils``, which is deprecated and was removed from the
    standard library in Python 3.12.

    ``packaging.version`` is deliberately not used: it applies PEP 440
    normalization (``"1.02"`` -> ``"1.2"``) and rejects many strings that
    LooseVersion accepted, which would change observable output.

    Degenerate inputs now fail with clear errors instead of the incidental
    ones LooseVersion produced: a non-string raises ``TypeError`` (previously
    ``TypeError`` for truthy values, ``AttributeError`` for ``None``), and an
    empty string raises ``ValueError`` (previously ``AttributeError``).
    """
    if not isinstance(value, str):
        raise TypeError(f"version must be a str, not {type(value).__name__}")
    if not value:
        raise ValueError("version must be a non-empty string")
    return value

def _legacy_loose_version():
    """Return distutils' LooseVersion if it is importable, else None.

    It is available from the stdlib on Python 3.10/3.11 and, on 3.12+, only
    via the shim that setuptools installs. Importing it can emit a
    deprecation warning, so suppress that here only.
    """
    with warnings.catch_warnings():
        warnings.simplefilter("ignore", DeprecationWarning)
        try:
            from distutils.version import LooseVersion
        except ImportError:
            return None
    return LooseVersion


class SlugifyTests(unittest.TestCase):
    def test_slugify(self):
        self.assertEqual(slugify("  Hello, World! "), "hello-world")

    def test_repeated_punctuation_collapses_to_single_separator(self):
        self.assertEqual(slugify("Hello,,, World!!!"), "hello-world")
        self.assertEqual(slugify("a--b__c..d"), "a-b-c-d")
        self.assertEqual(slugify("--edge--"), "edge")


class NormalizeVersionTests(unittest.TestCase):
    def test_normalize_version(self):
        self.assertEqual(normalize_version("1.2.0"), "1.2.0")
        self.assertEqual(normalize_version("2.0rc1"), "2.0rc1")

    def test_ordinary_versions_are_returned_unchanged(self):
        for version in ORDINARY_VERSIONS:
            with self.subTest(version=version):
                self.assertEqual(normalize_version(version), version)

    def test_no_pep440_rewriting(self):
        # Guards against swapping in packaging.version, which would give "1.2".
        self.assertEqual(normalize_version("1.02"), "1.02")

    def test_matches_legacy_loose_version(self):
        loose_version = _legacy_loose_version()
        if loose_version is None:
            self.skipTest("distutils.version is not importable on this interpreter")
        for version in ORDINARY_VERSIONS:
            with self.subTest(version=version):
                with warnings.catch_warnings():
                    # LooseVersion also warns on construction; the check is
                    # about slugkit, so silence the legacy side only.
                    warnings.simplefilter("ignore", DeprecationWarning)
                    legacy = str(loose_version(version))
                self.assertEqual(normalize_version(version), legacy)

    def test_does_not_emit_deprecation_warning(self):
        with warnings.catch_warnings(record=True) as caught:
            warnings.simplefilter("always")
            normalize_version("1.2.0")
        self.assertEqual([w for w in caught if issubclass(w.category, DeprecationWarning)], [])

    def test_module_does_not_import_distutils(self):
        import slugkit

        self.assertNotIn("distutils", vars(slugkit))
        self.assertNotIn("LooseVersion", vars(slugkit))

    def test_empty_string_is_rejected(self):
        with self.assertRaises(ValueError):
            normalize_version("")

    def test_non_string_is_rejected(self):
        for value in (None, 1, 1.2, b"1.2"):
            with self.subTest(value=value), self.assertRaises(TypeError):
                normalize_version(value)

import re

# Component splitter from distutils.version.LooseVersion, removed from the
# stdlib in Python 3.12. str() of that class returns the original spelling.
_COMPONENT_RE = re.compile(r"(\d+ | [a-z]+ | \.)", re.VERBOSE)


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


class _LooseVersion:
    """String-form stand-in for ``distutils.version.LooseVersion``.

    Numeric and alphabetic pieces are parsed, and ``str()`` returns the
    caller's spelling. Ordinary versions therefore keep leading zeros and
    pre-release suffixes.
    """

    def __init__(self, vstring: str | None = None) -> None:
        if vstring:
            self.parse(vstring)

    def parse(self, vstring: str) -> None:
        self.vstring = vstring
        components: list[int | str] = [
            part for part in _COMPONENT_RE.split(vstring) if part and part != "."
        ]
        for index, part in enumerate(components):
            try:
                components[index] = int(part)
            except ValueError:
                pass
        self.version = components

    def __str__(self) -> str:
        return self.vstring


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes."""
    return str(_LooseVersion(value))

import re

_VERSION_COMPONENT_RE = re.compile(r"(\d+|[a-z]+|\.)")


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes.

    Previously this used ``distutils.version.LooseVersion``, which was removed
    from the standard library in Python 3.12. That parser split the input into
    numeric/alphabetic components and returned the original string unchanged
    whenever parsing succeeded, raising ``ValueError`` when the string held no
    version components at all. This implementation keeps that contract, so
    ordinary versions (``1.2.0``) and pre-release forms (``2.0rc1``) are
    returned verbatim, and empty or component-free input is still rejected.
    """
    if not isinstance(value, str):
        raise TypeError(f"version must be a str, not {type(value).__name__}")
    components = [part for part in _VERSION_COMPONENT_RE.split(value) if part and part != "."]
    if not components:
        raise ValueError("empty version number")
    return value

Maintenance guide

Supported versions

slugkit supports Python 3.10 through 3.13. Every supported interpreter is exercised by the CI matrix in ci.yml, and pyproject.toml (requires-python, trove classifiers, ruff target-version) must always agree with that range. The runtime package intentionally has no third-party dependencies.

Compatibility policy

  • The public API is slugify and normalize_version. Behavior changes to these functions are announced in CHANGELOG.md and shipped in minor or major releases (the project follows semantic versioning; while version 0.x, breaking changes require at least a minor bump and a changelog entry).
  • normalize_version must keep returning ordinary version strings (including pre-release suffixes) unchanged, matching the historical str(distutils.version.LooseVersion(value)) output. Degenerate input raises TypeError (non-string) or ValueError (empty string).
  • Dropping a Python version: update requires-python, classifiers, ruff target-version, and the CI matrix in one release, and record the removal in the changelog.
  • Adding a newly released Python version: extend the CI matrix and classifiers as soon as the interpreter is available in actions/setup-python; support is only claimed after CI passes on it. No upper bound is declared in requires-python, so newer interpreters can install the package, but support is asserted only for versions validated in CI.
  • Replacing internals (as done for the deprecated version parsing in 0.4.0) must preserve observable output for ordinary inputs; stricter behavior is only allowed for inputs that previously failed incidentally, and must be documented.

Release checklist

  1. Confirm CI is green on all supported Python versions (3.10–3.13), including tests and ruff check ..
  2. Bump version in pyproject.toml.
  3. Write the release section in CHANGELOG.md: separate user-visible changes from internal maintenance, list known issues honestly, and do not claim fixes that did not land.
  4. Run local checks: python -m unittest discover -v and ruff check .; when a network is available, also python -m build and twine check dist/*.
  5. Commit the release, tag vX.Y.Z, and push the tag. (There is currently no automated publishing job; artifacts are built manually from the tag.)

Next maintenance items (prioritized)

  1. Unicode handling in slugify (user-visible known issue): non-ASCII letters are stripped instead of transliterated. Decide between an optional extra dependency or a small built-in fold table, define the documented guarantee, and cover it with tests.
  2. Strict version handling for normalize_version: current behavior is identity-preserving for compatibility. Evaluate adding PEP 440 validation/normalization behind a new, clearly named API (or opt-in keyword) so existing callers are unaffected, with tests for both modes.
  3. Release automation and CI reproducibility: add a publishing job for tagged releases (pinned actions, id-token: write scoped to that job only, everything else least-privileged) and pin ruff to a version range in CI so lint results are reproducible across runs.

import re


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes.

    Historically implemented as ``str(distutils.version.LooseVersion(value))``.
    ``LooseVersion.__str__`` returned the version string it was given
    unchanged, so for ordinary versions this function returns ``value`` as-is;
    that observable behavior is preserved. ``distutils`` is deprecated since
    Python 3.10 and removed in Python 3.12, so this replacement is
    dependency-free and raises explicit errors for degenerate input.
    """
    if not isinstance(value, str):
        raise TypeError(f"version must be a string, got {type(value).__name__}")
    if not value:
        raise ValueError("version string must not be empty")
    return value

"""Small slug and version helpers.

The version helper intentionally avoids :mod:`distutils`, which is deprecated
and no longer importable on the Python versions this package supports.
"""

import re

__all__ = ["normalize_version", "slugify"]

#: Any run of characters that is not a lowercase ASCII letter or digit.
_NON_SLUG = re.compile(r"[^a-z0-9]+")

#: Characters accepted in a version string. Deliberately permissive: the old
#: implementation accepted anything, and staying permissive keeps inputs that
#: used to be accepted still accepted.
_VERSION_CHARS = re.compile(r"\A[0-9A-Za-z.+_-]+\Z")

#: A leading "v" is conventional in VCS tags (``git tag v0.4.0``).
_TAG_PREFIXES = ("v", "V")


def slugify(value: str) -> str:
    """Return *value* lowercased with runs of non-alphanumerics collapsed to "-".

    Known limitation: non-ASCII letters are dropped rather than transliterated,
    so ``"café"`` becomes ``"caf"``. This is unchanged in 0.4.0.
    """
    value = value.strip().lower()
    return _NON_SLUG.sub("-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize an ordinary dotted version, preserving pre-release suffixes.

    ``normalize_version("1.2.0")`` and ``normalize_version("2.0rc1")`` are
    unchanged from the previous implementation: ``distutils.version.LooseVersion``
    tokenized its input for comparison only, and on the Python versions this
    package supports its ``__str__`` returned the original string unchanged.
    Re-deriving the string from those tokens would silently drop separators
    from valid forms such as ``"1.0.post1"`` or ``"1.0.dev4"``, so this
    function instead validates the input and returns it.

    Two conveniences are added, neither of which affects ordinary versions:
    surrounding whitespace is stripped, and a single leading ``"v"`` (as in a
    VCS tag) is removed.

    Raises:
        TypeError: if *value* is not a :class:`str`.
        ValueError: if *value* is empty or is not plausibly a version.
    """
    if not isinstance(value, str):
        raise TypeError(f"version must be a str, not {type(value).__name__}")

    version = value.strip()
    if version[:1] in _TAG_PREFIXES:
        version = version[1:]

    if not _VERSION_CHARS.match(version) or not any(ch.isdigit() for ch in version):
        raise ValueError(f"not a version string: {value!r}")

    return version

class SlugkitTests(unittest.TestCase):
    def test_slugify(self):
        self.assertEqual(slugify("  Hello, World! "), "hello-world")

    def test_slugify_collapses_repeated_punctuation(self):
        # Repeated separators were always collapsed to a single "-"; keep the
        # guarantee explicit rather than incidental to the regex.
        self.assertEqual(slugify("Hello---World!!"), "hello-world")
        self.assertEqual(slugify("a__b//c"), "a-b-c")
        self.assertEqual(slugify("---trim---"), "trim")

    def test_slugify_known_unicode_limitation(self):
        # Known limitation, NOT fixed in 0.4.0: non-ASCII letters are dropped
        # rather than transliterated. Pinned so that a future fix is a
        # deliberate, changelogged change.
        self.assertEqual(slugify("café"), "caf")

    def test_normalize_version(self):
        self.assertEqual(normalize_version("1.2.0"), "1.2.0")
        self.assertEqual(normalize_version("2.0rc1"), "2.0rc1")

    def test_normalize_version_ordinary_versions_are_unchanged(self):
        for value in ORDINARY_VERSIONS:
            with self.subTest(value=value):
                self.assertEqual(normalize_version(value), value)

    def test_normalize_version_strips_whitespace(self):
        self.assertEqual(normalize_version("  1.2.0  "), "1.2.0")

    def test_normalize_version_strips_single_tag_prefix(self):
        self.assertEqual(normalize_version("v0.4.0"), "0.4.0")
        self.assertEqual(normalize_version("V0.4.0"), "0.4.0")
        # Only a single leading "v" is removed.
        self.assertEqual(normalize_version("vv1.0"), "v1.0")

    def test_normalize_version_rejects_non_versions(self):
        for value in ["", "   ", "abc", "not a version!", "--", "1 2 3"]:
            with self.subTest(value=value):
                with self.assertRaises(ValueError):
                    normalize_version(value)

    def test_normalize_version_rejects_non_string(self):
        for value in [1.2, 120, None, ("1", "2")]:
            with self.subTest(value=value):
                with self.assertRaises(TypeError):
                    normalize_version(value)

        for value in ORDINARY_VERSIONS:
            with self.subTest(value=value):
                self.assertEqual(normalize_version(value), str(LooseVersion(value)))

    """Normalize ordinary dotted versions, preserving pre-release suffixes.

    This previously delegated to ``distutils.version.LooseVersion``, which was
    removed from the standard library in Python 3.12. ``LooseVersion.__str__``

    and ``"2.0rc1"`` round-trip unchanged; this implementation preserves that
    observable behavior without any dependency on ``distutils``.
    """
    return value

Maintenance Guide

This document describes how slugkit is released, what its compatibility commitments are, and what the maintainers should focus on next.

Release Checklist

For every minor or major release, the following steps must pass before tagging a release:

  1. Decide the version bump. Patch releases are bug fixes that preserve observable behavior; minor releases may change or remove deprecated APIs; major releases may break the public surface. This release is 0.4.0, a minor bump that drops Python 3.9 and replaces an internal dependency.
  2. Update pyproject.toml. Bump version, confirm requires-python matches the supported range, and confirm declared dependencies are still correct.
  3. Refresh CHANGELOG.md. Move the in-progress entry from "Unreleased" to a dated heading and ensure user-visible and internal changes are listed separately.
  4. Update ci.yml. Make sure the Python matrix matches the supported range, and that actions/checkout@v4 and actions/setup-python@v5 remain pinned (no floating to @latest).
  5. Run local checks. Install the package in editable mode, run python -m unittest discover -v, and run ruff check .. All must pass.
  6. Tag the release. Create a git tag of the form v<version> and push it. No additional network publishing is configured in this repository.
  7. Sanity check the distribution build. Run python -m pip wheel --no-deps -w dist/ and inspect the produced wheel name to confirm metadata is correct.

Compatibility Policy

slugkit follows these compatibility commitments:

  • Python versions. The currently supported range is >=3.10,<3.14 (3.10, 3.11, 3.12, 3.13). New Python versions are added to the matrix and pyproject.toml when their first stable release ships; old versions are dropped when they reach end-of-life upstream.
  • Public API. The two public functions slugify and normalize_version are stable within a major version. Behavior changes go through a minor release with a changelog entry.
  • Dependencies. Runtime dependencies are kept to a small set (packaging is currently the only one) and are pinned with a lower bound chosen so that any supported version satisfies it.
  • Internal modules. Replacing or removing internals (such as the move from distutils.version to packaging.version) does not require a major version bump as long as the public API's observable behavior is preserved.

Next Three Prioritized Maintenance Items

  1. Improve Unicode handling in slugify (known limitation). Non-ASCII letters are dropped rather than transliterated. The 0.4.0 release explicitly does not claim to fix this. The next step is to evaluate unicodedata.normalize("NFKD", ...) plus an ASCII filter, gated by a regression test that pins the chosen transliteration policy.
  2. Move to a src/ layout with explicit package data. The repository currently ships a flat module. Moving to src/slugkit/__init__.py would prevent accidental imports from the working directory and make the wheel contents easier to audit.
  3. Add a build/distribution verification job to CI. The release checklist calls for a local wheel build, but CI does not yet run python -m build or upload artifacts. Adding this step would catch metadata regressions (wrong requires-python, missing files) before tagging a release.

import re

from packaging.version import InvalidVersion, Version


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes."""
    try:
        return str(Version(value))
    except InvalidVersion:
        # Preserve observable behavior for ordinary dotted versions.
        # Anything we cannot parse is surfaced to the caller unchanged.
        return value

import re

_VERSION_RE = re.compile(r"^\d+(?:\.\d+)*(?:[a-z]+\d*)?$", re.ASCII)


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes.

    Accepts ordinary dotted versions with an optional lowercase pre-release
    suffix (for example ``1.2.0`` or ``2.0rc1``) and returns them unchanged,
    matching the output of the previous distutils-based implementation for
    such versions. Strings that do not follow this form raise ``ValueError``
    and non-string input raises ``TypeError``.
    """
    if not isinstance(value, str):
        raise TypeError(f"version must be str, not {type(value).__name__}")
    if _VERSION_RE.match(value) is None:
        raise ValueError(f"invalid version string: {value!r}")
    return value

import re


def slugify(value: str) -> str:
    value = value.strip().lower()
    return re.sub(r"[^a-z0-9]+", "-", value).strip("-")


def normalize_version(value: str) -> str:
    """Normalize ordinary dotted versions, preserving pre-release suffixes."""
    # Simple normalization for common version patterns:
    # - dotted versions (1.2.3)
    # - pre-release suffixes (rc, alpha, beta, dev, post)
    # This mimics distutils.LooseVersion behavior for ordinary versions.
    pattern = r"^(\d+(?:\.\d+)*)((?:[ab]|rc|dev|post)\d*)?$"
    match = re.match(pattern, value.strip())
    if match:
        return match.group(1) + (match.group(2) or "")
    # Fallback: return as-is for unrecognized patterns
    return value.strip()

Complete the following checklist when preparing and publishing a release:

  1. Run Unit Tests: Execute all local unit tests to ensure complete pass:
    python -m unittest -v

    python -m build
  7. Publish and Tag: Create a Git release tag and publish release artifacts to PyPI:
    git tag v<version>
git push origin v<version>
twine upload dist/*

Compatibility Policy

  • Supported Python Versions: slugkit officially supports active Python releases, currently Python 3.10 through 3.13. Support for Python versions is retired once they reach upstream End-of-Life (EOL). New Python versions are evaluated and added to CI validation as they become available.
  • Semantic Versioning (SemVer):
    • Major releases (X.0.0): Incompatible API changes or dropping supported Python versions outside standard maintenance.
    • Minor releases (0.X.0): Backward-compatible feature additions, deprecation milestones, and scheduled Python compatibility updates.
    • Patch releases (0.0.X): Backward-compatible bug fixes and internal maintenance.
  • Version Normalization Guarantees: normalize_version guarantees PEP 440-compliant normalization for ordinary dotted versions and pre-release/post-release identifiers.

    • Priority: High (User-facing feature improvement).

  2. Automated Continuous Delivery (CD):

    • Description: Establish a GitHub Actions deployment workflow utilizing PyPI Trusted Publishing (OIDC) triggered automatically upon creating a new release tag, avoiding manual build and upload steps.
    • Priority: Medium (Release automation & security).
